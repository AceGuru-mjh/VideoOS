# i18n 双语支持 / Bilingual i18n Support

> Studio 界面的全面中英双语系统：词典、Provider、质量门禁（键位奇偶 + 调用点覆盖 + 双语渲染冒烟）、本地化格式工具与语言探测。本文为双语特性的参考文档， deliberately bilingual —— 中文版在前，English version 在后半部分。
>
> The complete Chinese/English bilingual system for the Studio UI: dictionaries, provider, CI-enforced quality gates (key parity + call-site coverage + dual-locale render smoke), locale-aware formatting helpers and language detection. 中文版见上半部分。

## 中文版

### 1. 总览

VideoOS Studio 的全部用户可见文案都经由 i18n 系统输出，支持中文（zh）与英文（en）即时切换，零刷新。词典规模：**每语言 841 键**（common 500 + chat 341），覆盖 IDE 界面、向导（含模型配置）、对话主界面、S5 可视化面板（管线/用量/预览）、**S6 设置中心（九大类：通用/模型/Agent/渲染/MCP/Skills/界面/隐私/高级）**、Skills/MCP 面板、权限弹窗与服务端错误码。系统由四层组成：

- **纯逻辑核心**（`apps/studio/src/i18n/core.ts`）—— 词典查词、键位展开、词典合并，无 React 依赖，可独立测试；
- **React 层**（`apps/studio/src/i18n/index.tsx`）—— `I18nProvider` + `useI18n`，语言状态的事实源与持久化；
- **词典**（`apps/studio/src/i18n/locales/`）—— 按「段所有权」拆分为 common / chat 两组聚合进总词典；
- **配套工具** —— `format.ts`（Intl 本地化格式）、`detect.ts`（浏览器语言探测）、`errors.ts`（服务端错误码本地化）。

四层全部有模块级测试覆盖，并被 CI 强制（见 §4）。

### 2. 架构

```text
main.tsx
  └─ <I18nProvider>                    唯一语言事实源
       └─ 组件树
            └─ const { t, locale, setLocale } = useI18n()
                 └─ t("topbar.compile")            点路径查词
                    t("statusbar.diagTitle",       {param} 插值
                      { errors: 2, warnings: 3 })
```

- **`core.ts`** 导出：`translate(dict, key, params?)`（点路径查词；**缺失键回显键本身**——开发期可见、生产不崩溃；`{param}` 占位插值）、`flattenKeys`（词典 → 点路径键列表，奇偶校验用）、`mergeDicts`（顶层段合并）、`section`（读取平铺 dotted-key 子表）、`topLevelOverlap`（段互斥校验用）。类型 `Locale = "zh" | "en"`、`Dictionary`。
- **`index.tsx`** 导出 `I18nProvider` / `useI18n`。`useI18n()` 必须在 Provider 内调用，返回 `{ locale, t, setLocale }`。`setLocale` 即时切换：写 localStorage（键 `videoos.language`）+ 异步同步服务端 `settings.general.language`，同时把 `document.documentElement.lang` 更新为 `zh-CN` / `en`（无障碍与输入法提示）。
- **聚合器 `zh.ts` / `en.ts`**：`mergeDicts(zhCommon, zhChat)` —— common 与 chat 两份分词典按顶层段合并为总词典，同名段后者覆盖（测试保证不会发生）。

### 3. 词典与段所有权

词典按「段」组织，每个顶层段有唯一属主文件，两组互斥（`i18n.test.ts` 用 `topLevelOverlap` 断言为空）：

| 属主文件 | 段 | 内容 |
| --- | --- | --- |
| `locales/zh-common.ts` / `en-common.ts` | `topbar` `app` `welcome` `wizard` `modelStep` `settings` `statusbar` `dock` `editor` `preview` `timeline` `project` `renderDialog` `diagnostics` `tests` `events` `agent` `chatStream` `ui` `errors` | 既有 IDE 界面 + 向导（含 S2 模型配置）+ **S6 设置中心（导航/九页/重置，178 键）** + 消息流/任务卡共享段 + 通用 UI 原语 + 服务端错误码 |
| `locales/zh-chat.ts` / `en-chat.ts` | `chatView` `chat` `sessions` `taskCard` `skills` `mcp` `context` `pipeline` `usage` `chatPreview` `permissions` `confirm` | 对话子系统：ChatView 外壳、Composer 输入框、会话列表、任务卡、Skills/MCP 面板与设置页、右栏可视化页签容器（预览/管线/用量）、S5 管线与用量面板、会话内播放器、Agent 权限编辑器（设置中心共享）、确认卡 |

规则：

1. **一个键只属于一个段**；新增段前先确认没有同名顶层段（互斥测试会拦截）。
2. zh 与 en 的键位必须**完全一致**（`flattenKeys` 排序后逐项相等）—— 漏译即测试红。
3. 值为纯字符串，参数用 `{name}` 占位；**刻意不翻译技术串**（文件路径、工具名、codec/preset 值、环境变量名、`videoos` 品牌与版本号、QA 术语 golden/diff 等）。

### 4. 质量门禁（测试与 CI）

`bun test apps/studio/src/i18n` 跑四个测试文件，CI（`.github/workflows/ci.yml` 的 `bun test packages apps`）逐 PR 强制：

| 文件 | 门禁 | 失败时机 |
| --- | --- | --- |
| `i18n.test.ts` | zh/en 键位奇偶、common/chat 段互斥、translate 行为 | 漏译 / 段越界 / 查词回归 |
| `coverage.test.ts` | **已使用键覆盖**：扫描 `apps/studio/src/**/*.{ts,tsx}`（跳过 `i18n/` 与 `*.test.*`）里所有 `t("字面量键")` 调用，逐一核对词典 | 组件用了一个词典里没有的键——失败信息列出每个 `文件:行 → "键"` |
| `coverage.test.ts`（同文件） | **未使用键报告**：词典中没有任何扫描源引用的键 → `console.log` 汇总（仅记录，不失败） | 永不失败；`errors.*` 等动态键（`t(\`errors.${code}\`)`）与经辅助常量消费的键天然不可静态见 |
| `render.test.tsx` | 双语 SSR 渲染冒烟（`react-dom/server`）：Provider 下 `t()` 输出对应语言、缺失键回显键本身、参数插值、localStorage 读取路径、纯组件（ui 原语/Markdown/TaskCard）双语渲染不抛错 | Provider / 回退 / 插值行为回归 |
| `format.test.ts` | `format.ts` + `detect.ts` 全量单元测试（两种语言、非法输入、边界） | 格式化 / 探测回归 |

覆盖测试的扫描器自带「健康断言」：至少扫到一个源文件与一个已使用键，防止正则失效后测试空洞转绿。

配套的伴生测试 `components/chat/viz-data.test.ts`（不在 `i18n/` 目录，随 S5 数据层）用真实词典验证可视化层的双语输出（管线步骤名、用量趋势行 title 的 zh/en 插值）与冻结的工具→步骤映射、截断安全解析。

另有开发侧体检工具 `bun run i18n:report`（`scripts/i18n-report.ts`）：词典覆盖汇总（键量/奇偶/分段计数/t() 字面量扫描）+ 硬编码 CJK 回归扫描（逐字符状态机，剥注释、感知引号；`--strict` 时命中即退出码 1，可作本地门禁）。存量 17 处命中均为声明的刻意保留（正则协议匹配、labelZh 数据字段、主题双语品牌名）。

### 5. 如何新增一条文案

以给欢迎页加「示例提示」为例：

1. **定位段属主**：Welcome 属于既有 UI → `locales/zh-common.ts` / `en-common.ts` 的 `welcome` 段。
2. **双语同时加键**（点路径一致）：
   ```ts
   // zh-common.ts
   welcome: { /* … */ demoHint: "这是一个示例提示" }
   // en-common.ts
   welcome: { /* … */ demoHint: "this is a demo hint" }
   ```
3. **组件内消费**：
   ```tsx
   import { useI18n } from "../i18n";
   export function Welcome() {
     const { t } = useI18n();
     return <p>{t("welcome.demoHint")}</p>;
   }
   ```
4. **带参数**：词典值写 `"已编译 {frames} 帧"`，调用 `t("statusbar.compiled", { frames: 120 })`。
5. **验证**：`bun test apps/studio/src/i18n`（奇偶 + 覆盖全绿）与 `bun run --filter @videoos/studio typecheck`。

红线：不要在 JSX 里硬编码用户可见字符串；不要只加一种语言；不要把技术串（路径/命令/工具名）塞进词典。

### 6. 本地化格式工具（format.ts）

纯函数、无 React，统一走 `Intl`（zh → `zh-CN`，en → `en-US`）：

| 函数 | zh 输出 | en 输出 |
| --- | --- | --- |
| `formatDateTime(locale, iso)` | `10月5日 14:30` | `Oct 5, 2:30 PM` |
| `formatNumber(locale, n)` | `1,234` | `1,234` |
| `formatCount(locale, n, unit)` | `1,250 tokens` | `1,250 tokens` |
| `formatDurationMs(ms)` | `980ms` / `1.2s` / `1m03s`（技术单位，两语言一致） | 同左 |
| `formatRelativeTime(locale, iso, t)` | `3分钟前` | `3 minutes ago` |

- 非法输入一律返回 `""`，绝不抛错（坏时间戳不能打崩渲染）。
- `formatDurationMs` 与 `components/chat/util` 的 `fmtDuration` 逐字节一致（有逐值断言），调用方可无损迁移。
- `formatRelativeTime` 分桶：< 60 秒 → `t("chatStream.relNow")`（常量 `RELATIVE_JUST_NOW_KEY`，"刚刚" / "just now"）；分钟 / 小时 / 天走 `Intl.RelativeTimeFormat`；≥ 7 天回退 `formatDateTime` 绝对日期；未来时间自动渲染 "in …"/"…后"。`t` 以参数注入保持纯函数可测。

### 7. 语言探测与持久化

语言解析优先级（`I18nProvider` 启动逻辑）：

```text
localStorage["videoos.language"]      用户显式选择（最高优先，含刷新持久）
  → detectBrowserLocale(               本地无偏好时按浏览器语言探测（detect.ts）
      navigator.languages)             zh* → zh、en* → en、全不认识 → zh；SSR/无 navigator 回退 zh
  → 服务端 settings.general.language  同样仅本地无偏好时采纳（GET /api/settings，端点不可达静默跳过）
  → "zh"                             默认
```

`setLocale` 双写：localStorage + `PATCH /api/settings { general: { language } }`（服务端失败不影响本地切换）。

**浏览器语言自动探测（`detect.ts`，已接线）**：`detectBrowserLocale(navigator.languages)` 按 BCP-47 偏好顺序取第一个可识别标签——`zh*` → `zh`、`en*` → `en`、全不认识 → 回退 `zh`。首访（本地无存储偏好）时作为默认值，用户显式切换后 localStorage 永远优先。

### 8. 语言切换入口

- **TopBar 中/EN 分段按钮**（`seg-toggle`，`aria-pressed` 标记当前语言）—— 全局入口，任何界面模式可见；
- **对话模式 ChatView 顶栏** —— 同款切换钮（已落地，位于 ws 状态指示之前）。

切换即时生效：所有 `t()` 订阅重渲，`html lang` 跟随，无需刷新。

### 9. 错误码本地化

服务端错误形如 `"SESSION_NOT_FOUND: session abc"`，也可能是裸码 `"SESSIONS_LOAD_FAILED"`（客户端合成错误）。`i18n/errors.ts` 的 `useApiErrorMessage()`：

1. 正则匹配 `^([A-Z][A-Z0-9_]+)(?:: (.*))?$` 提取错误码（detail 可选）；
2. 已知码 → `t(\`errors.${code}\`)` 本地化；带 detail 时在括号里保留（`会话不存在 (session abc)`），裸码则纯本地化文案；
3. 未知码 / 非码文本（如网络层 "cannot reach videoos server: …"）→ 原样透传，绝不吞错。

新增服务端错误码时：在抛出点用 `SERVER_*` / `SESSION_*` 等大写码前缀，同时在**两份**词典 `errors` 段补 `errors.<CODE>` 键。注意 `errors.*` 是动态键（模板字符串拼键），覆盖扫描器看不见它——由词典奇偶测试与人工评审兜底。

### 10. 服务端双语层

服务端同样按 `settings.general.language` 输出双语文本（`packages/server/src/server-messages.ts`）：

- **`errorDetail(settings, detail)`** —— 服务端错误 detail 的双语表（精确 + 模板双层，动态段回填），`app.onError` 统一接线；zh 恒原样返回（源语言即中文）；
- **LLM 回复语言对齐** —— orchestrator 系统提示按设置追加语言行（en："- Always reply to the user in English." / zh："请始终用简体中文回复用户。"），助手回复语言跟随 UI 语言；
- **`mcpHint(values)`** —— /api/mcp 的安装提示双语。

### 11. 约定与常见问题

- **`t` 变量遮蔽**：`map((t) => …)` 会遮蔽 i18n 的 `t` —— 循环变量改名（`tr`/`tab`/`sec`），已有先例。
- **动态键**：`t(\`dock.${id}\`)` 无法静态检查，集中在 `errors.*`、`dock.*` 等小而稳定的段；新增动态段请评估加显式键枚举。
- **单复数**：中文键直接写 `"N 个错误"`；英文用双键（`errorSingular` / `errorPlural`）或 `{word}` 参数传单复数词。
- **`useI18n` 必须在 Provider 内**：`main.tsx` 在根组件挂 `<I18nProvider>`；测试里渲染 i18n 组件也要包 Provider（`render.test.tsx` 有范例）。
- **测试文件命名**：`*.test.ts(x)` 会被覆盖扫描跳过——测试里的 `t()` 调用不需要进词典。

## English Version

### 1. Overview

Every user-visible string in VideoOS Studio flows through the i18n system, with instant Chinese (zh) / English (en) switching and no reloads. Dictionary scale: **841 keys per language** (500 common + 341 chat), covering the IDE surface, the wizard (including model configuration), the chat main surface, the S5 visualization panels (pipeline/usage/preview), **the S6 settings center (nine categories: General/Models/Agent/Render/MCP/Skills/Interface/Privacy/Advanced)**, the Skills/MCP panels, the permissions modal and server error codes. Four layers:

- **Pure core** (`apps/studio/src/i18n/core.ts`) — dictionary lookup, key flattening, dictionary merging; no React dependency, independently testable;
- **React layer** (`apps/studio/src/i18n/index.tsx`) — `I18nProvider` + `useI18n`, the single source of truth for language state and persistence;
- **Dictionaries** (`apps/studio/src/i18n/locales/`) — split by section ownership into common / chat, aggregated into the master dictionaries;
- **Companion utilities** — `format.ts` (Intl-based formatting), `detect.ts` (browser language detection), `errors.ts` (server error-code localization).

All four layers are covered by module-level tests, enforced by CI (see §4).

### 2. Architecture

```text
main.tsx
  └─ <I18nProvider>                    single source of truth
       └─ component tree
            └─ const { t, locale, setLocale } = useI18n()
                 └─ t("topbar.compile")            dotted-path lookup
                    t("statusbar.diagTitle",       {param} interpolation
                      { errors: 2, warnings: 3 })
```

- **`core.ts`** exports: `translate(dict, key, params?)` (dotted-path lookup; **a missing key echoes the key itself** — visible in development, never crashes production; `{param}` placeholder interpolation), `flattenKeys` (dictionary → dotted-key list, used by parity checks), `mergeDicts` (top-level section merge), `section` (reads a flat dotted-key sub-table), `topLevelOverlap` (section-exclusivity check). Types `Locale = "zh" | "en"`, `Dictionary`.
- **`index.tsx`** exports `I18nProvider` / `useI18n`. `useI18n()` must be called inside the provider and returns `{ locale, t, setLocale }`. `setLocale` switches instantly: writes localStorage (key `videoos.language`) + asynchronously syncs the server's `settings.general.language`, and updates `document.documentElement.lang` to `zh-CN` / `en` (accessibility + IME hints).
- **Aggregators `zh.ts` / `en.ts`**: `mergeDicts(zhCommon, zhChat)` — common and chat sub-dictionaries merge by top-level section into the master dictionary (same-named sections would be overwritten; tests guarantee that never happens).

### 3. Dictionaries and Section Ownership

Dictionaries are organized by top-level section, each with exactly one owning file; the two groups are mutually exclusive (`i18n.test.ts` asserts `topLevelOverlap` is empty):

| Owning files | Sections | Contents |
| --- | --- | --- |
| `locales/zh-common.ts` / `en-common.ts` | `topbar` `app` `welcome` `wizard` `modelStep` `settings` `statusbar` `dock` `editor` `preview` `timeline` `project` `renderDialog` `diagnostics` `tests` `events` `agent` `chatStream` `ui` `errors` | existing IDE surface + wizard (incl. model config) + **S6 settings center (nav/nine pages/reset, 178 keys)** + message-stream/task-card shared sections + shared UI primitives + server error codes |
| `locales/zh-chat.ts` / `en-chat.ts` | `chatView` `chat` `sessions` `taskCard` `skills` `mcp` `context` `pipeline` `usage` `chatPreview` `permissions` `confirm` | chat subsystem: ChatView shell, Composer input, session list, task card, Skills/MCP panels & settings pages, right-rail visualization tabs (preview/pipeline/usage), S5 pipeline & usage panels, in-chat player, Agent policy editor (shared with settings center), confirm card |

Rules:

1. **A key belongs to exactly one section**; confirm no same-named top-level section exists before adding one (the exclusivity test will catch it).
2. zh and en key sets must be **identical** (`flattenKeys` sorted, item-by-item equal) — a missing translation fails the test.
3. Values are plain strings with `{name}` placeholders; **technical strings are deliberately not translated** (file paths, tool names, codec/preset values, environment variable names, the `videoos` brand and version, QA terms like golden/diff).

### 4. Quality Gates (Tests and CI)

`bun test apps/studio/src/i18n` runs four test files, enforced per-PR by CI (`.github/workflows/ci.yml`, step `bun test packages apps`):

| File | Gate | Fails when |
| --- | --- | --- |
| `i18n.test.ts` | zh/en key parity, common/chat section exclusivity, translate behavior | missing translation / section overreach / lookup regression |
| `coverage.test.ts` | **used-key coverage**: scans `apps/studio/src/**/*.{ts,tsx}` (skipping `i18n/` and `*.test.*`) for every `t("literal.key")` call and checks each against the dictionary | a component uses a key the dictionary does not have — the failure lists every `file:line → "key"` |
| `coverage.test.ts` (same file) | **unused-key report**: dictionary keys no scanned source references → `console.log` summary (informational, never fails) | never; dynamic keys (`t(\`errors.${code}\`)`) and keys consumed via helper constants are inherently invisible to a static scanner |
| `render.test.tsx` | dual-locale SSR render smoke (`react-dom/server`): `t()` output follows the provider locale, missing keys echo the key, params interpolate, the localStorage read path works, and pure components (ui primitives/Markdown/TaskCard) render under both locales without throwing | provider / fallback / interpolation behavior regressions |
| `format.test.ts` | full unit tests for `format.ts` + `detect.ts` (both locales, invalid inputs, boundaries) | formatting / detection regressions |

The coverage scanner carries its own health assertion — it must find at least one source file and one used key — so a broken regex can never silently turn the gate green.

A companion suite `components/chat/viz-data.test.ts` (outside `i18n/`, owned by the S5 data layer) verifies the visualization layer's bilingual output against the real dictionaries (pipeline step names, usage trend-row titles with zh/en interpolation) plus the frozen tool→step mapping and truncation-safe parsing.

A developer-facing health tool `bun run i18n:report` (`scripts/i18n-report.ts`) summarizes dictionary coverage (key counts / parity / per-section counts / t()-literal scan) and runs a hardcoded-CJK regression scan (character-by-character state machine, comment-stripping, quote-aware; `--strict` exits 1 on any hit, usable as a local gate). The 17 standing hits are all declared intentional (regex protocol matching, labelZh data fields, dual-language theme brand names).

### 5. How to Add a New String

Adding a "demo hint" to the welcome screen, for example:

1. **Find the section owner**: Welcome is existing UI → the `welcome` section in `locales/zh-common.ts` / `en-common.ts`.
2. **Add the key to BOTH dictionaries** (same dotted path):
   ```ts
   // zh-common.ts
   welcome: { /* … */ demoHint: "这是一个示例提示" }
   // en-common.ts
   welcome: { /* … */ demoHint: "this is a demo hint" }
   ```
3. **Consume it in the component**:
   ```tsx
   import { useI18n } from "../i18n";
   export function Welcome() {
     const { t } = useI18n();
     return <p>{t("welcome.demoHint")}</p>;
   }
   ```
4. **With parameters**: dictionary value `"✓ compiled {frames}f"`, call `t("statusbar.compiled", { frames: 120 })`.
5. **Verify**: `bun test apps/studio/src/i18n` (parity + coverage green) and `bun run --filter @videoos/studio typecheck`.

Red lines: never hardcode user-visible strings in JSX; never add only one language; keep technical strings (paths/commands/tool names) out of the dictionaries.

### 6. Locale-Aware Formatting (format.ts)

Pure functions, no React, all backed by `Intl` (zh → `zh-CN`, en → `en-US`):

| Function | zh output | en output |
| --- | --- | --- |
| `formatDateTime(locale, iso)` | `10月5日 14:30` | `Oct 5, 2:30 PM` |
| `formatNumber(locale, n)` | `1,234` | `1,234` |
| `formatCount(locale, n, unit)` | `1,250 tokens` | `1,250 tokens` |
| `formatDurationMs(ms)` | `980ms` / `1.2s` / `1m03s` (technical unit, identical in both locales) | same |
| `formatRelativeTime(locale, iso, t)` | `3分钟前` | `3 minutes ago` |

- Invalid input returns `""` — never throws (a broken timestamp must not crash a render pass).
- `formatDurationMs` matches `components/chat/util`'s `fmtDuration` byte-for-byte (asserted value-by-value), so call sites can migrate losslessly.
- `formatRelativeTime` buckets: < 60 s → `t("chatStream.relNow")` (constant `RELATIVE_JUST_NOW_KEY`, "刚刚" / "just now"); minutes / hours / days via `Intl.RelativeTimeFormat`; ≥ 7 days falls back to the absolute `formatDateTime`; future timestamps render "in …"/"…后" automatically. The `t` function is injected as a parameter to keep this pure and testable.

### 7. Language Detection and Persistence

Resolution priority at provider startup:

```text
localStorage["videoos.language"]      explicit user choice (top priority, survives reloads)
  → detectBrowserLocale(               browser-language detection when no local preference (detect.ts)
      navigator.languages)             zh* → zh, en* → en, nothing recognizable → zh; SSR/no-navigator falls back to zh
  → server settings.general.language  likewise adopted only when no local preference exists
                                      (GET /api/settings; silently skipped if unreachable)
  → "zh"                             default
```

`setLocale` writes both sides: localStorage + `PATCH /api/settings { general: { language } }` (a server failure never blocks the local switch).

**Browser language auto-detection (`detect.ts`, wired)**: `detectBrowserLocale(navigator.languages)` walks the BCP-47 preference order and picks the first recognizable tag — `zh*` → `zh`, `en*` → `en`, nothing recognizable → fallback `zh`. It serves as the default on first visit (no stored preference); once the user switches explicitly, localStorage always wins.

### 8. Language Toggle Entry Points

- **TopBar 中/EN segmented button** (`seg-toggle`, `aria-pressed` marks the active language) — the global entry, visible in every UI mode;
- **ChatView header in chat mode** — the same toggle style (landed, placed before the ws status indicator).

Switching is instant: every `t()` subscription re-renders, `html lang` follows, no reload.

### 9. Error-Code Localization

Server errors arrive as `"SESSION_NOT_FOUND: session abc"`, or as a bare code like `"SESSIONS_LOAD_FAILED"` (client-synthesized). `useApiErrorMessage()` from `i18n/errors.ts`:

1. matches `^([A-Z][A-Z0-9_]+)(?:: (.*))?$` to extract the code (detail optional);
2. known code → `t(\`errors.${code}\`)` localization, keeping the detail in parentheses when present (`会话不存在 (session abc)`); bare codes render the localized text alone;
3. unknown codes / non-code text (e.g. the network layer's "cannot reach videoos server: …") → passed through verbatim, never swallowed.

When adding a server error code: throw with an uppercase `SERVER_*` / `SESSION_*`-style prefix, and add the `errors.<CODE>` key to **both** dictionaries. Note that `errors.*` is a dynamic key (template-literal key construction) invisible to the coverage scanner — parity tests and review are the backstop there.

### 10. Server-Side Bilingual Layer

The server also emits bilingual text driven by `settings.general.language` (`packages/server/src/server-messages.ts`):

- **`errorDetail(settings, detail)`** — a bilingual table for server error details (exact + template tiers, dynamic segments refilled), wired once in `app.onError`; zh always returns the detail verbatim (Chinese is the source language);
- **LLM reply-language alignment** — the orchestrator appends a language line to the system prompt per settings (en: "- Always reply to the user in English." / zh: "请始终用简体中文回复用户。"), so assistant replies follow the UI language;
- **`mcpHint(values)`** — the bilingual install hint from /api/mcp.

### 11. Conventions and FAQ

- **`t` shadowing**: `map((t) => …)` shadows the i18n `t` — rename loop variables (`tr`/`tab`/`sec`); precedents exist in the codebase.
- **Dynamic keys**: `t(\`dock.${id}\`)` cannot be checked statically; keep them confined to small, stable sections (`errors.*`, `dock.*`); consider an explicit key enumeration for new dynamic sections.
- **Plurals**: Chinese keys can say `"N 个错误"` directly; English uses paired keys (`errorSingular` / `errorPlural`) or a `{word}` parameter carrying the pluralized word.
- **`useI18n` requires a provider**: `main.tsx` mounts `<I18nProvider>` at the root; tests rendering i18n components must wrap them too (see `render.test.tsx` for a working example).
- **Test file naming**: `*.test.ts(x)` files are skipped by the coverage scanner — `t()` calls inside tests never need dictionary entries.
